# 研学打卡闯关功能 Spec

## 1. 背景

家庭旅行中的景点通常包含历史、地理、气候、人文、政治、工程、艺术等知识，但孩子在现场容易只停留在“看过”和“拍照”。研学功能的目标是把每个景点转化为可参与、可记录、可复盘的闯关任务，让小学和初中孩子在旅行中形成真实收获。

## 2. 目标

- 每个景点生成一张“研学任务卡”，包含故事、观察、提问、打卡和复盘。
- 支持小学低年级、小学高年级、初中三个难度层级。
- 支持现场闯关：找线索、拍照、回答问题、完成小实验或表达任务。
- 支持 A4 下载/打印，也支持手机分享。
- 与行程日、景点、待办联动，不影响现有同行只读分享能力。

## 3. 用户角色

- 家长：选择难度、下载卡片、查看完成情况。
- 孩子：按任务卡完成观察、答题、拍照、表达和闯关。
- 同行成员：可查看孩子成果，分享页默认只读。

## 4. 核心玩法

### 4.1 景点任务卡

每个景点生成 1 张主卡，包含：

- `故事引子`：用 100-150 字讲清背景，不堆知识点。
- `今日身份`：如“小小地理观察员”“古建侦探”“红色交通员”。
- `3 个观察任务`：现场能完成，例如找碑文、看地形、听水声、观察建筑结构。
- `2 个闯关问题`：必须能从现场或卡片信息推理得到。
- `1 个表达任务`：一句话讲给家人听、画路线、写一句发现。
- `完成徽章`：按主题发放，如“太行山地形徽章”“黄河水文徽章”。

### 4.2 闯关模式

```ts
score = observeTasks.done * 10
  + quiz.correct * 15
  + reflection.done * 20
  + photoCheckin.done * 10

if (score >= 80) badge = '金牌研学官'
if (score >= 60) badge = '完成闯关'
else badge = '继续探索'
```

关卡类型：

- `观察关`：到现场找证据。
- `推理关`：根据故事和现场信息回答为什么。
- `表达关`：讲述、画图、写一句总结。
- `协作关`：家长和孩子互问互答。
- `复盘关`：当天晚上整理 3 个收获。

### 4.3 年龄分层

小学低年级：

- 题目短，重观察和表达。
- 多用选择、连线、涂色、找一找。
- 单张卡任务 15-20 分钟。

小学高年级：

- 增加因果推理和时间线。
- 引导孩子比较“过去和现在”“自然和人类活动”。
- 单张卡任务 20-30 分钟。

初中：

- 增加历史背景、地理成因、政策制度和社会影响。
- 鼓励写 80-150 字观点。
- 单张卡任务 30-45 分钟。

## 5. 示例：长治 / 黄崖洞

任务卡主题：太行山里的兵工厂

- 故事引子：黄崖洞位于太行山深处，峡谷、山体和交通条件让这里成为重要的隐蔽地点。孩子需要观察地形如何保护工厂，也要理解战争年代物资、道路和安全之间的关系。
- 今日身份：太行山地形侦察员。
- 观察任务：
  - 找到一处能说明“易守难攻”的地形。
  - 记录峡谷里的温度、风、水声或岩壁特点。
  - 找一个与兵工生产相关的展品或遗址。
- 闯关问题：
  - 为什么兵工厂不建在平原城市？
  - 山区隐蔽带来了哪些好处，又带来了哪些困难？
- 表达任务：用 3 句话向同行讲清“地形如何影响历史”。
- 徽章：太行山地形徽章。

## 6. A4 卡片设计

单页 A4 竖版：

- 顶部：景点名称、日期、Day、难度、预计耗时。
- 左栏：故事引子、今日身份、知识关键词。
- 右栏：观察任务、闯关问题、完成勾选。
- 底部：我的发现、家长签名、二维码/分享链接。

下载格式：

- MVP：浏览器打印样式，支持 `window.print()` 生成 PDF。
- P1：生成独立 A4 HTML 打印页。
- P2：服务端生成 PDF，支持批量下载整日或整趟行程卡片。

## 7. 页面与交互

新增入口：

- `/trip/[id]/study`：研学任务总览。
- `/trip/[id]/study/[spotId]`：单景点任务卡。
- `/trip/[id]/study/print`：A4 批量打印页。

行程页集成：

- 在景点类 `event.category === 'spot'` 的 TimelineCard 上显示“研学闯关”入口。
- 行程总览显示“今日研学进度”。
- 分享页可只读查看任务和成果，不允许改答案。

## 8. 数据模型草案

```ts
type StudyLevel = 'lower_primary' | 'upper_primary' | 'middle_school';
type StudyTaskType = 'observe' | 'quiz' | 'photo' | 'reflection' | 'collaboration';

interface StudyCard {
  id: string;
  tripId: string;
  dayId: string;
  eventId: string;
  title: string;
  theme: string;
  level: StudyLevel;
  story: string;
  roleName: string;
  estimatedMinutes: number;
  keywords: string[];
  badgeName: string;
  tasks: StudyTask[];
}

interface StudyTask {
  id: string;
  cardId: string;
  type: StudyTaskType;
  prompt: string;
  options?: string[];
  answerHint?: string;
  points: number;
  sortOrder: number;
}

interface StudyProgress {
  id: string;
  cardId: string;
  taskId: string;
  userId?: string;
  status: 'open' | 'done';
  answerText?: string;
  photoUrl?: string;
  completedAt?: string;
}
```

## 9. Supabase 持久化草案

后续需要云端同步时新增：

- `study_cards`
- `study_tasks`
- `study_progress`
- `study_badges`

安全原则：

- public schema 新表启用 RLS。
- owner/editor 可创建和修改卡片。
- viewer 只读。
- 孩子的答案、照片和签名默认不对匿名公开。
- 分享页通过服务端 token 校验后返回只读数据，不直接开放 `anon` 表访问。

## 10. AI 生成策略

输入：

- 景点名称、城市、行程日期、孩子年龄段、旅行主题、已有资料文本。

输出：

- 严格 JSON，不直接输出 Markdown。
- 每张卡最多 6 个任务，避免现场负担过重。
- 问题必须能通过现场观察、资料卡或常识推理完成。
- 禁止生成需要危险动作、攀爬、脱离家长视线的任务。

质量规则：

- 先讲故事，再问问题。
- 任务要具体到“看什么、找什么、说什么”。
- 每个任务有明确完成条件。
- 每张卡至少覆盖一个跨学科点：历史 + 地理、人文 + 政治、气候 + 工程等。

## 11. 分阶段实现

MVP：

- 用静态 seed 为长治相关景点生成研学卡。
- 在行程详情接入“研学闯关”入口。
- 单景点卡片支持勾选、答题、本地状态。
- A4 打印页支持浏览器打印。

P1：

- 接入 AI 生成研学卡。
- 支持按年龄层重新生成。
- 支持整日卡片批量打印。
- 本地保存孩子答案和完成徽章。

P2：

- Supabase 同步研学卡、进度、照片和徽章。
- 分享页展示只读成果。
- 旅行结束自动生成“研学成长报告”。

## 12. 验证标准

- 小学生卡片 15-20 分钟内可完成。
- 初中卡片至少包含一个需要因果解释的问题。
- A4 打印不截断、不依赖深色背景。
- 分享页不出现可编辑控件。
- 无网络时静态卡片仍可查看和打印。
