## 目标

本次优化把行程详情从“分享型只读展示”拆成“管理型工作台”和“同行只读页”：

- 所有页面共享页头、页脚。
- 页头展示当前北京时间和当日已排期时段。
- 行程管理支持待办完成勾选、每日快速跳转、行前/行中/行后动态语义。
- 行程总览增加目的地地图化展示，当前先以内置长治点位呈现，后续可接高德地图。

## 前端状态

当前版本仍以静态 seed 和浏览器本地状态为主：

- `TripWorkspace` 负责行程工作台。
- `TripTodo.status` 是服务端持久化字段，前端本次用 `doneTodoIds` 做本地交互预演。
- `getTripScheduleContext` 已根据 `Asia/Shanghai` 日期判断 `pretrip`、`intrip`、`posttrip`。

## v1.1.0 变更：轨迹地图模块

「不新增前端依赖」这条约束已作废。假地图（OSM iframe + 经纬度线性归一化的绝对定位点）无法画线、无法动画，也无法正确投影，因此引入 `leaflet@^1.9.4`（动态分包，不进主 bundle）。

### 单一真源

轨迹不再来自平行维护的点位清单，而是从 `trip.days[].events[].geo` 派生：

```
buildJourneyTrack(trip, overlay) -> JourneyTrack
  排序键 (dayIndex, startTime ?? '99:99', 原数组下标)
  缺 geo 的事件进 unresolvedEventIds，UI 提示「N 个行程点待补坐标」
  按 eventId 合并覆盖层，优先级：用户覆盖 > 事件字段
```

`getDestinationMapPoints(destination)` 的「长治」字符串硬匹配与 `lib/mock/destination-map.ts` 一并删除。任何行程只要事件带 `geo`，地图模块即可用——这是「未来行程按同一套规划、管理、展示、归档」的落点。

### 覆盖层（图片与故事）

`JourneyOverlay` 按 `eventId` 索引 `{ imageUrl, story, tags }`，种子数据随代码走，用户编辑存 `localStorage`（key `travelflow:journey-overlay:{tripId}:v1`），支持 JSON 导入导出。仅在 `useEffect` 内读取，首屏仍渲染种子，避免 hydration mismatch。

图片网址只接受 `https:`、站内 `/` 路径与 `data:image/*`（值最终进 `img src`）。使用原生 `<img>` 而非 `next/image`：`next.config.mjs` 的 `remotePatterns` 只白名单了 `images.unsplash.com`，任意图床会 400。附带 `referrerPolicy="no-referrer"` 以绕过国内图床的防盗链。

### 路网是渐进增强，不是依赖

OSRM 公共 demo server 无 SLA，`routing.openstreetmap.de` 的条款亦不承诺生产可用。因此：

- 首屏与播放起步一律使用 2km 步长加密的直线示意路径，动画立即可用。
- 仅在用户点播放时才请求路网，不在挂载时请求。
- 逐段隔离（单段失败只让该段回落直线，不整天降级），6s 超时，并发 3，`sessionStorage` 缓存。
- `transportMode: 'flight' | 'walk'` 的段不请求驾车路由，直接画直线。
- UI 明示「公路路线 / 示意路线」，失败不阻断。

后续正解是 `app/api/route/route.ts` 服务端代理（顺带消灭 CORS，并把换用高德收敛成一个环境变量），本版未做。

### 全屏

以 portal 到 `body` 的 `fixed inset-0 z-[60] h-[100dvh]` 浮层为主，而非 Fullscreen API——iPhone Safari 不实现 `requestFullscreen`，且 portal 能逃出祖先 `transform` 对 `position:fixed` 的破坏。附 iOS 滚动锁、ESC 关闭与焦点归还。

### 已知取舍

地图画布在嵌入态与全屏态之间移动时会 remount，路网几何与车辆位置由容器在 `[baseLayer, expanded]` 的 effect 中重放。

## 2026-08-17：动态执行层

当前本地版本已增加行程执行日志：

- 第一次打开行程时保存不可变初始快照。
- 修改、取消、跨天移动、顺延、交换、实际完成和撤销统一追加 change，不覆盖初始计划。
- 当前行程由快照和有效 change 折叠得到，按 `travelflow:execution:${tripId}` 保存。
- 取消项目仍保留在“已取消”区域，用于恢复和复盘；本地版本不提供永久删除。
- 行程执行复盘只统计可由快照和日志重算的事实，AI 推测与事实分开。

附近决策助手当前只排序现有行程中带坐标的未完成项目。浏览器位置需要用户主动授权，只在当前页面内存中使用，不写入 localStorage。外部助手入口采用“复制推荐问题/系统分享”，不会声称已经读取商业平台数据。

## 外部推荐数据落地条件

### 高德地图

高德 Web 服务地点搜索 2.0 支持周边搜索。生产接入需要：

1. 申请 Web 服务 API Key；
2. 通过服务端 Route Handler 请求 `https://restapi.amap.com/v5/place/around`，Key 不下发浏览器；
3. 返回结果标记来源与查询时间，并对营业状态做“待核验”降级；
4. 结合距离、类别、当前剩余时间筛选，不把高德综合排序解释为 TravelFlow 评分。

官方文档：<https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch>。

### 美团、大众点评、携程

美团生态开放平台要求先申请合作并经过商务评估、方案确认、开发测试和上线验收；携程开发者能力也需要应用授权或业务合作。未获得正式许可前：

- 不抓取网页；
- 不调用私有接口；
- 不展示伪造的评分、实时价格、库存或“多平台综合推荐”；
- 只提供带当前行程上下文的检索问题和官方入口。

官方入口：<https://openapi.meituan.com/>、<https://developer.ctrip.com/>。
