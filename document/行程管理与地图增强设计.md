# 行程管理与地图增强设计

| 文档类型 | 版本 | 日期 | 状态 |
| --- | --- | --- | --- |

## 目标

本次优化把行程详情从“分享型只读展示”拆成“管理型工作台”和“同行只读页”：

- 所有页面共享页头、页脚。
- 页头展示当前北京时间和当日已排期时段。
- 行程管理支持待办完成勾选、每日快速跳转、行前/行中/行后动态语义。
- 行程总览增加目的地地图化展示，当前先以内置长治点位呈现，后续可接高德地图。

## 前端状态

当前版本仍以静态 seed 和浏览器本地状态为主：

- `TripWorkspace` 负责行程工作台。
- `TripTodo.status` 是服务端持久化字段，前端本次用 `doneTodoIds` 做本地交互预演。
- `getTripScheduleContext` 已根据 `Asia/Shanghai` 日期判断 `pretrip`、`intrip`、`posttrip`。
- `DestinationMap` 使用 `destination` 匹配 `changzhiMapPoints`，不新增前端依赖。

## 展示规则

```ts
if (now < firstDay.date) {
  view = '未成行规划管理';
  visibleDay = firstDay;
  nextAction = firstDay.events[0];
}

if (firstDay.date <= now && now <= lastDay.date) {
  view = '行中管理';
  visibleDay = dayByCurrentDate;
  nextAction = nextEventByCurrentTime;
}

if (now > lastDay.date) {
  view = '行后归档';
  visibleDay = lastDay;
}
```

## Supabase 扩展

对应 SQL 文件：`db/itinerary-management-extension.sql`。

新增或扩展：

- `events.status`
- `events.sort_order`
- `events.navigation_url`
- `todos`
- `destination_map_points`

安全策略：

- 新增 public 表启用 RLS。
- 仅 `authenticated` 用户访问。
- 读写都通过 `trips.user_id = auth.uid()` 约束到行程所有者。
- 新项目 Data API 默认可能不自动暴露新表，因此 SQL 显式 `grant` 给 `authenticated`。

## 后续接入

1. 将待办勾选从本地 state 改为 Server Action 更新 `public.todos.status`。
2. 从 `public.destination_map_points` 读取城市点位。
3. 地图 SDK 接入时优先使用高德地图，静态地图作为无 Key 降级视图。
4. 同行分享若需要匿名访问，不直接开放表给 `anon`，改由服务端校验分享 token 后返回只读数据。
