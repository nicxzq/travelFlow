# 官方平台搜索跳转设计

## 1. 结论

TravelFlow 不接管美团、大众点评、携程或高德的个人账号，不保存密码、Cookie、Session，也不模拟登录抓取结果。

当前实现采用官方跳转：TravelFlow 根据当前位置、可用时间和查询场景生成搜索关键词；高德使用官方 URI API 直接携带关键词和坐标搜索，美团、大众点评、携程复制关键词后打开官方 HTTPS 入口。用户如需登录，只在对应官方 App 或网站内完成。

## 2. 为什么

- 高德公开提供 URI 搜索协议，支持 `keyword`、`center`、`city` 和 `callnative`；这是无需消费者账号即可使用的正式跳转能力。
- 高德结构化 POI 搜索需要开发者 Key，与个人高德账号登录无关。
- 美团和携程公开平台面向合作伙伴接入，当前没有核实到允许任意第三方通过消费者个人 OAuth 读取餐厅、酒店、点评和价格的通用接口。
- 模拟个人登录会把账号封禁、凭据泄露、条款变化和反爬失败风险转嫁给用户，不能作为旅行现场的可靠主路径。
- Vercel Marketplace 未发现美团、携程或高德的可安装集成。

## 3. 方案比较

### A. 托管个人账号或 Cookie

拒绝。风险不可控，且 TravelFlow 会接触高敏凭据；平台页面或风控变化也会让能力随时失效。

### B. 等待企业合作 API

保留为未来升级方向，但不能阻塞当前使用。只有取得正式合作资质、授权范围和稳定接口后，才允许在 TravelFlow 内展示结构化平台结果。

### C. 关键词 + 官方入口

当前采用。虽然多一次跳转，且无法在 TravelFlow 内直接比较价格和点评，但上线快、零凭据托管、失败时仍可手动粘贴关键词。

## 4. 交互设计

在“附近决策助手”中新增查询场景：

- 半天游玩：地点 + 附近 + 半天 + 亲子/少走路 + 景点；
- 吃饭：地点 + 附近 + 当地特色 + 适合家庭 + 性价比；
- 住宿：地点 + 附近 + 家庭房 + 停车 + 性价比。

平台入口：

- 高德地图：使用 `https://uri.amap.com/search`，携带关键词、可用时带入当前位置坐标，并设置 `callnative=1`。移动端优先尝试唤起 App，失败后保留网页结果。
- 美团、大众点评、携程：先复制场景关键词，再打开对应官方 HTTPS 入口。若浏览器拒绝剪贴板，页面保留可选中的关键词供用户手动复制。

每次点击后显示可访问状态提示，例如“关键词已复制，已打开美团；请在官方平台内登录并粘贴搜索”。

## 5. 数据与安全边界

- 不收集或持久化第三方账号、密码、Cookie、Session、订单和浏览历史。
- 不使用爬虫读取搜索结果，不转录受版权保护的点评原文。
- 当前位置只在用户主动授权后用于本次高德 URI；不写入本地存储或服务端。
- URL 只允许官方 HTTPS 域名；不使用未经公开文档确认的私有 URL Scheme。
- TravelFlow 只生成检索意图，不宣称已经综合了平台评分、价格或实时营业信息。

## 6. 未来升级条件

满足以下任一条件后，才能把外部跳转升级为站内聚合：

1. 平台公开消费者级 OAuth 和所需的结构化搜索、点评、价格接口；
2. TravelFlow 获得正式合作伙伴资质、书面授权和稳定的生产配额。

升级时仍保留官方跳转作为核验和故障降级路径。

## 7. 验收标准

- 三种场景均能生成包含当前地点和明确约束的短关键词。
- 高德 URL 使用官方 URI 域名，正确编码关键词和可选坐标。
- 美团、大众点评、携程只打开官方 HTTPS 域名，并先尝试复制关键词。
- 剪贴板失败时关键词仍可见、可选中。
- UI 明确说明 TravelFlow 不接触平台账号，也未读取平台评分和价格。
- 纯函数测试覆盖关键词、官方域名、编码和坐标顺序。
