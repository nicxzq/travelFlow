# 研学闯关参考内容与孩子答案设计

| 项目 | 内容 |
| --- | --- |
| 日期 | 2026-08-16 |
| 状态 | 已决策 |
| 范围 | 静态研学卡、逐题参考内容、孩子答案与浏览器本地保存 |

## 1. 目标

每道研学任务都允许孩子记录自己的观察或回答，同时提供默认折叠的参考内容。孩子应先独立思考，需要帮助时才展开参考内容；刷新页面后答案和完成状态不能丢失。

本次不等待云端协作工程，先完成当前浏览器内的可靠记录。跨设备同步仍属于后续 Supabase `study_progress` 阶段。

## 2. 方案选择

比较三个方案：

1. 每张卡只有一个总答案框：实现最少，但无法对应具体问题，复盘价值低。
2. 每题独立答案和独立参考折叠：问题、孩子答案、参考思路一一对应，最适合现场完成和后续复盘。
3. 立即增加 Supabase 研学表：可跨设备，但会与尚未实施的云端权限工程耦合，扩大本次范围。

采用方案 2，并使用版本化 localStorage。它直接解决当前问题，也为以后迁移到 `study_progress` 保留稳定 task id。

## 3. 数据模型

每个 `StudyTask` 增加：

```ts
type StudyTask = {
  id: string;
  type: 'observe' | 'quiz' | 'reflection';
  prompt: string;
  referenceAnswer: string;
};
```

`id` 必须显式、稳定且与数组顺序无关，例如 `huangyadong-observe-terrain`。不再使用 `${card.id}-${index}`，避免任务排序改变后把旧答案绑定到错误题目。

本地记录结构：

```ts
type StudyStorageV1 = {
  version: 1;
  completedTaskIds: string[];
  answers: Record<string, string>;
  updatedAt: string;
};
```

localStorage key 为 `travelflow:study:${tripId}`，不同旅行互不影响。

## 4. 交互

每道题依次显示：

1. 完成勾选与任务正文；
2. 孩子的答案输入区；
3. 默认收起的参考内容按钮；
4. 展开后的参考内容。

三类任务都使用 textarea：observe/quiz 为 2 行，reflection 为 3 行。手机上不会因为长答案被单行输入框截断。

参考内容命名：

- quiz：`查看参考答案` / `收起参考答案`；
- observe/reflection：`查看参考思路` / `收起参考思路`。

每题独立展开，初始均为收起。按钮使用 `aria-expanded`、`aria-controls`；参考内容容器使用稳定 id、`role="region"` 和带题目上下文的 `aria-label`。

## 5. 保存与恢复

`TripWorkspace` 是研学状态的唯一来源，`TimelineCard` 保持受控组件，不直接访问 localStorage。

- 首次挂载时读取一次并校验 `version/completedTaskIds/answers`。
- 答案或完成状态变化后 400ms 防抖写入。
- 非空答案首次保存时自动标记任务完成。
- 手动取消完成不会删除答案。
- 没有文字也允许手动完成，适用于现场观察或口头表达。
- 答案 trim 后为空时删除对应 key，但不自动取消完成状态。
- 非法 JSON 或结构不合法时删除损坏缓存并回退空状态，页面不崩溃。
- 删除任务后遗留的孤儿 key 不渲染；MVP 不做主动清理。

## 6. 只读与隐私

只读分享页：

- 不显示可编辑 textarea；
- 如果当前浏览器有孩子答案，以纯文本显示；没有则显示“还没有作答”；
- 完成勾选不可修改；
- 参考内容仍可展开，因为这是阅读行为。

当前答案只存在本地浏览器，不会因分享链接自动传给其他设备。因此本次不会扩大孩子数据的公开范围。未来接入 Supabase 时，孩子答案默认不得向匿名 viewer 公开，需要单独的成果分享授权。

## 7. 参考内容规则

- quiz 给出简洁、事实审慎的参考答案。
- observe/reflection 给参考思路，不把开放观察变成唯一答案。
- 文案面向小学阶段，通常 1–3 句话。
- 鼓励孩子使用自己的话，不要求照抄。
- 不编造现场一定存在的标识、装饰或自然现象；使用“可以观察”“可能看到”等表述。
- 蒲津渡只说明铁牛作为浮桥地锚的工程作用，不写缺少权威依据的具体朝向。

## 8. 错误处理

- localStorage 不可用：继续允许当前页面答题，刷新后不保证恢复；页面不崩溃。
- 写入失败：保留 React 内存状态，不阻塞继续答题。
- 参考内容缺失：类型测试和数据测试失败，阻止合入。
- 同一 task id 重复：数据测试失败，防止答案串题。

## 9. 验收标准

1. 所有现有研学任务都有稳定、唯一的 id 和非空 referenceAnswer。
2. 所有参考内容默认收起，逐题展开/收起且无障碍状态正确。
3. 输入答案 400ms 后写入 `travelflow:study:${tripId}`。
4. 刷新后答案与完成状态恢复。
5. 首次输入非空答案自动完成；手动取消不清空答案。
6. 清空答案会删除存储 key，但不强制取消任务。
7. 非法本地数据不会导致页面崩溃。
8. 只读页不能改答案，但可查看当前浏览器已有答案和展开参考内容。
9. 不同 trip、不同 card、不同 task 的答案不会串扰。
10. `npm test`、`npm run typecheck` 和 `npm run build` 通过。
